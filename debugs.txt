  2. Implemented Fixes

  Fix A: Robust Supabase Client Initialization
  We moved the Supabase client creation strictly inside AuthContext to ensure it's managed by the React lifecycle, preventing
  stale instances.

  File: src/utils/supabase/client.ts

   import { createBrowserClient } from '@supabase/ssr'
   import { Database } from '@/types/database'

   export const createClient = () => {
     const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
     const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;

     if (!supabaseUrl) throw new Error('Missing env: NEXT_PUBLIC_SUPABASE_URL');
     if (!supabaseAnonKey) throw new Error('Missing env: NEXT_PUBLIC_SUPABASE_ANON_KEY');

     return createBrowserClient<Database>(supabaseUrl, supabaseAnonKey);
   }
   // Removed: export const supabase = createClient() (Global instance removed)

  Fix B: Handling Aborts & Timeouts (The "Infinite Loading" Fix)
  We modified fetchWithRetry to:
   1. Ignore AbortErrors: If a request is cancelled (user navigated away), return null instead of throwing.
   2. Add Timeouts: Wrap the Supabase query in Promise.race with a 10-second timer to prevent hanging forever.

  File: src/app/perfume/[id]/page.tsx (Inside fetchWithRetry)

   const fetchWithRetry = async (retries = 3): Promise<Perfume | null> => {
     try {
       if (abortController.signal.aborted) return null; // Early exit

       if (!supabase) throw new Error('Supabase client is not available.');

       // 1. Connection Test (Non-blocking warning)
       const { error: testError } = await supabase.from('perfumes').select('id').limit(1).abortSignal(abortController.signal);
       if (testError) console.warn('Supabase connection test warning:', testError);

       // 2. Main Query with 10s Timeout
       const { data: mainPerfume, error } = await Promise.race([
         supabase
           .from('perfumes')
           .select(`...fields...`)
           .eq('id', id)
           .abortSignal(abortController.signal)
           .maybeSingle(),
         new Promise<{ data: null; error: any }>((_, reject) =>
           setTimeout(() => reject(new Error('Request timed out')), 10000)
         )
       ]);

       if (error) throw new Error(`Database query failed: ${error.message}`);
       
       // ... validation logic ...
       
       return mainPerfume as unknown as Perfume;

     } catch (err: any) {
       // 3. Graceful Abort Handling
       if (err.name === 'AbortError' || abortController.signal.aborted) {
           return null; // Silent return on navigation

  3. Best Practices for Future Reference

   1. Always use Timeouts: When fetching data (especially from external services like Supabase), never assume the network will
      respond. Always race against a timeout.
   2. Respect `AbortController`: In React useEffect, always handle the AbortError. It is not a "bug" but a feature of navigating
      away.
   3. Hooks at Top Level: Never place useEffect or other hooks inside if, for, or while blocks. They must run in the exact same
      order on every render.
   4. Auth Context as Source of Truth: Avoid global Supabase client instances in Next.js App Router. Let AuthContext or Server
      Components manage the client creation.
